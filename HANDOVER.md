# MESHi — developer handover

One-page website for MESHi restaurant (Plzeň, CZ). Astro, static output, no UI
framework, hand-written CSS. Builds to plain HTML, hosted on Cloudflare Pages.

- Production domain: https://meshi-restaurant.eu (set in `astro.config.mjs`)
- Current deployment: https://meshi-restaurant.pages.dev

---

## 1. Run and build

```bash
npm install
npm run dev      # http://localhost:4321
npm run build    # outputs to dist/
npm run preview  # serve the built output
```

Node 18+. There are no tests and no linter.

## 2. Deploy

Cloudflare Pages, **direct upload** — the project is not connected to git, so
pushing code does *not* trigger a deploy. Deploy explicitly:

```bash
npm run build
npx wrangler@latest pages deploy dist --project-name=meshi-restaurant --branch=main
```

`--branch=main` is required. Without it Cloudflare treats the upload as a preview
deployment and the production domain stays unchanged.

## 3. Layout of the repo

```
src/
  pages/index.astro        the whole page — only composes components in order
  layouts/Base.astro       <head>, OG/Twitter meta, JSON-LD, font + script tags
  components/              one file per section (Hero, About, Signatures, ...)
  data/menu.ts             categories, dishes, image paths
  styles/global.css        ALL the CSS, numbered sections 1-20
public/
  js/app.js                all behaviour: nav, scrollspy, menu overlay, lightbox, forms
  js/i18n.js               CZ/EN dictionary
  vendor/                  GSAP + ScrollTrigger + Lenis (pinned copies)
  assets/menu/             dish photos, generated by a script (see §5)
  _headers                 cache + security headers for Cloudflare
  google-rating.json       Google score, read by app.js at runtime
scripts/                   asset generators, not part of the build
```

**Why CSS and JS sit outside the bundler:** `global.css` is hand-written and the
design is signed off, so it is not going through Tailwind and selectors are not
being refactored. `app.js` reads the globals `gsap` / `ScrollTrigger` / `Lenis`,
which must exist before it runs — hence everything is loaded with `is:inline`
from `public/`; a bundler would reorder them.

## 4. What is NOT finished

The most important part of this document.

| Area | State |
|---|---|
| Reservation form `#resForm` | **Submits nowhere.** `wire()` in [`public/js/app.js`](public/js/app.js) only validates, shows the success message and resets. The guest believes a table was booked; the restaurant receives nothing. |
| Gift voucher form `#vForm` | Same — same `wire()` function. |
| "Online objednávka" button | `#objednavka` in `Header.astro` and its twin in `Sheet.astro` have **no handler at all**. |
| "Privacy policy" / "Terms" links | `href="#"` in `Footer.astro` and inside the GDPR consent label in `Reserve.astro`. The forms collect name/phone/e-mail, so this is a legal gap, not just a UX one. |

When wiring the forms up: show `#resOk` / `#vOk` **after** a successful response,
not before the request like the current placeholder does.

## 5. Asset generators

Run by hand when needed; they are not part of `npm run build`:

| Script | Purpose |
|---|---|
| `scripts/build-menu-images.py` | Source dish photos → `public/assets/menu/` (WebP, 4:5 covers and 4:3 tiles, each with @2x) |
| `scripts/build-patterns.py` | Generates the Japanese pattern SVGs in `public/assets/art/` |
| `scripts/build-jp-subset.sh` | Subsets the Japanese font. The full face is 1.3 MB to draw 24 characters, so the repo only carries the 50 KB subset — rerun this if new Japanese text is added. |
| `scripts/build-favicons.py` | favicon.ico + favicon-32 + apple-touch-icon from `assets/meshi_logo_hero.png` |
| `npm run rating:google` | Pulls the Google score into `public/google-rating.json` via the Places API. `placeId` in that file is currently empty so the script cannot run yet; the present numbers (4.9 / 252) were filled in by hand. |

Needs `pillow`, and `fonttools` + `brotli` for the font subset, in a virtualenv.

## 6. Conventions

- **i18n**: never hard-code copy beyond the Czech default. Add `data-i18n="key"` to
  the element and the key to both dictionaries in `public/js/i18n.js`. Variants:
  `data-i18n-html`, `-placeholder`, `-aria`, `-alt`, `-title`.
- **Responsive**: the CSS is desktop-first and every mobile rule lives in section 19
  of `global.css`, on the 1180 / 900 / 760 / 620 / 400 px ladder. The 760 and 620
  blocks are where mobile density was tightened — edit those instead of adding new
  breakpoints.
- **Animation**: GSAP + ScrollTrigger, all declared in `app.js`. There is a
  `prefers-reduced-motion` path and a `no-js` path; keep both working when adding
  effects.
- **Images**: live in `public/` and are plain `<img>` (not `astro:assets` yet).
  Anything below the fold needs `loading="lazy"` plus `width`/`height` so the
  layout does not shift.

## 7. SEO and performance already in place

- `public/_headers`: `/fonts`, `/_astro`, `/vendor` cached for a year as immutable;
  `/assets` and `/docs` for 7 days (image filenames are not hashed, so nothing
  longer); `google-rating.json` for 5 minutes. Plus `nosniff`, `Referrer-Policy`
  and `X-Frame-Options`.
- JSON-LD `Restaurant` in `Base.astro`: address, coordinates, opening hours, menu
  PDF, and a rating read from `google-rating.json` at build time so the structured
  data can never drift from what the page shows.
- OG/Twitter card image at `public/assets/og-cover.jpg` (1200×630).
- Static `robots.txt` and `sitemap.xml` in `public/`.

**Known cost, left as is:** `public/assets/background_video.mp4` is 16.2 MB
(1920×1080, 41 s, 3.15 Mbps) and autoplays, so phones download all of it. Kept on
the client's instruction. Re-encoding to 720p/CRF 32 would land around 2 MB and
look the same on screen, since the video is dimmed and covered by three gradient
veils anyway.
